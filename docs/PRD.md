# Job Search Assistant 产品需求文档

## 1. 文档信息

- 产品名称：Job Search Assistant
- 当前版本：PRD v0.3
- 首发平台：Boss 直聘 Web
- 产品形态：自动投递 Skill + Kimi WebBridge + 项目 Chrome 扩展 + 本地知识库服务 + 用户自选云端大模型
- 目标用户：需要批量分析职位、定制求职材料并辅助投递的求职者

## 2. 产品目标

Job Search Assistant 帮助用户在处理大量职位时完成以下工作：

1. 获取并结构化解析职位 JD。
2. 识别学历偏好、工作方式、行业和其他用户自定义风险条件。
3. 从用户本地的项目库、经历库和简历库中检索与 JD 相关的真实材料。
4. 判断是否具备生成定制简历和个性化问候语的充分依据。
5. 资料不足、匹配度低或命中风险条件时，自动回退到默认简历和默认问候语。
6. 用户确认投递配置并启动任务后，由 Skill 编排 Kimi 执行 Boss 沟通和问候语发送；默认简历图片由项目 Chrome 扩展发送。
7. 保存投递材料版本、求职申请和阶段事件，为投递漏斗与材料优化提供可追溯数据。

## 3. 非目标

第一版不包含：

- 自动编造项目、技能、学历、成果或量化指标。
- 没有用户主动启动任务的后台投递。
- 自动回复招聘者的后续聊天。
- Boss 直聘以外的招聘平台。
- 基于投递结果自动训练模型。
- 团队协作、企业招聘和 SaaS 管理后台。

## 4. 产品原则

### 4.1 真实性

生成的每条简历内容必须关联到经过用户确认的事实来源。没有来源的内容不得进入最终简历。

### 4.2 本地优先

项目、简历、个人资料、向量索引和投递记录默认保存在本机。云端模型只接收当前任务命中的必要片段。

### 4.3 可降级

任何 AI、RAG、模板渲染或文件生成环节失败时，不应中断整批任务，而应回退到默认简历和默认问候语。

### 4.4 用户控制

用户主动启动投递任务后，系统无需逐项或批量确认即可连续执行；用户可以随时暂停或停止任务。平台风控、账号限额、黑名单和重复职位会自动中止或跳过。

## 5. 核心概念

### 5.1 求职目标

由用户输入的职位方向，例如“AI 应用开发工程师”或“Java 后端工程师”。每个目标独立关联：

- 岗位关键词；
- 城市、薪资和行业偏好；
- 默认简历；
- 默认问候语；
- 风险规则；
- 匹配阈值；
- 简历模板。

### 5.2 风险条件

用户不希望在 JD 中看到、但默认不阻止投递的条件，例如：

- 985、211 或第一学历偏好；
- 外包、驻场；
- 单休、大小周；
- 特定行业或公司类型；
- 超出期望范围的经验要求。

命中风险条件时，职位使用默认简历和默认问候语。用户可将特定规则手动改成“禁止投递”。

### 5.3 岗位适合度

衡量用户与岗位要求的匹配程度，不代表材料生成质量。

### 5.4 定制可信度

衡量本地知识库中是否存在足够、真实且可引用的材料来生成定制简历。

只有岗位适合度和定制可信度均达到用户阈值时，系统才生成定制材料。

## 6. 用户流程

### 6.1 首次使用

1. 安装本地服务、Kimi Browser Extension、BOSS Skill 和项目 Chrome 图片扩展。
2. 创建本地用户档案。
3. 填写个人基本信息。
4. 创建一个或多个求职目标。
5. 上传历史简历并指定默认简历。
6. 设置默认问候语。
7. 连接 GitHub 并选择需要导入的项目。
8. 审核系统生成的项目资料和标签。
9. 配置云端模型 API。
10. 设置匹配阈值和风险规则。
11. 如需发送图片，重新导入简历生成首页图片、设置默认图片，并显式开启随投递发送。

### 6.2 项目入库

1. 用户提供 GitHub 仓库地址。
2. 本地服务读取仓库元数据和允许分析的文件。
3. 系统生成项目背景、职责、技术栈和候选标签。
4. 用户补充业务背景、个人职责和成果。
5. 用户确认事实及其可使用范围。
6. 本地服务生成结构化事实和向量索引。

### 6.3 职位分析与投递

1. Skill 通过 Kimi 从带目标关键词和城市的 Boss 搜索页获取职位列表和完整 JD。
2. 系统解析岗位要求并保留证据原文。
3. 执行风险规则和重复职位检查。
4. 本地 RAG 检索相关项目、经历和简历片段。
5. 云端模型生成匹配报告。
6. 根据双阈值选择定制材料或默认材料。
7. 系统展示目标、阈值、规则、默认问候语、默认图片配置状态和图片开关，用户确认后启动任务。
8. Skill 调用本地原子分析接口逐条决策；Kimi 连续执行沟通和问候语发送。
9. 图片开关开启且默认图片已配置时，Skill 调用项目扩展先加载预览、再确认发送；BOSS 在文件注入后立即发送。
10. 系统保存职位、判断、问候语、图片发送详情和投递结果，并在结束时生成 HTML 汇总。
11. 用户可从职位快照列表点击“跟进”；当前实现使用兼容弹窗和布尔汇总字段，正式申请事件时间线仍在建设。

## 7. 投递决策

| 状态 | 简历 | 问候语 | 默认动作 |
| --- | --- | --- | --- |
| 高匹配且资料充分 | 定制简历 | 个性化问候语 | 任务启动后自动投递 |
| 一般匹配 | 默认简历 | 默认问候语 | 任务启动后自动投递 |
| 命中风险条件 | 默认简历 | 默认问候语 | 任务启动后自动投递 |
| AI 或生成失败 | 默认简历 | 默认问候语 | 任务启动后自动投递 |
| 重复职位 | 无 | 无 | 默认阻止，可人工覆盖 |
| 公司黑名单 | 无 | 无 | 禁止投递 |
| 平台限额或风控 | 无 | 无 | 立即停止任务 |

双阈值不写死在 Skill 或扩展中，以 `GET /v1/automation/config` 返回值为准。适合度未达阈值时拒绝投递；适合度达标但定制可信度不足时使用默认材料。

## 8. 功能需求

### 8.1 用户档案

- 维护基本信息、教育、工作经历、技能和联系方式。
- 字段可设置为：本地私密、允许发给模型、允许写入简历、允许写入问候语。
- 支持导入 PDF、DOCX 和 Markdown 简历。

### 8.2 求职目标

- 支持多个目标。
- 支持目标关键词、城市、薪资、行业和工作方式。
- 每个目标可设置默认材料、风险规则、阈值和模板。

### 8.3 GitHub 项目库

- 添加、更新、禁用和删除项目。
- 保存仓库地址、分支和同步版本。
- 自动提取技术栈和候选标签。
- 用户确认后才能将自动提取内容用于简历。
- 支持用户手工补充非代码事实。
- 私有仓库支持列为待确认项，第一阶段可先完成公开仓库。

### 8.4 标签体系

标签至少分为：

- 技术标签：Vue、Python、RAG、PostgreSQL 等；
- 业务标签：招聘、企业服务、电商、内容平台等；
- 能力标签：系统设计、性能优化、数据建模等；
- 角色标签：独立开发、负责人、协作者等；
- 结果标签：增长、降本、提效、稳定性等。

系统推荐标签，用户可以增加、删除、合并和确认。

### 8.5 JD 获取与解析

- 支持 Boss 职位列表和详情页。
- 保存原始 JD、来源 URL、采集时间和页面职位 ID。
- 提取职责、技能、经验、学历、学校偏好、薪资、地点和福利。
- 每个结构化判断必须保存对应的原文证据。
- 区分“硬性要求”“优先条件”“公司介绍”和“否定表达”。

### 8.6 规则引擎

- 支持关键词、数值、公司、行业和语义规则。
- 动作支持：提醒、降分、使用默认材料、禁止投递。
- 默认风险规则只将职位降级到默认材料。
- 规则结果必须展示命中证据。

### 8.7 RAG 检索

- 本地执行标签过滤、关键词检索、向量召回和重排。
- 只检索允许用于当前场景的事实。
- 返回来源 ID、相关性分数和原始证据。
- 不把整个知识库发送给云端模型。

### 8.8 匹配报告

报告至少包含：

- 岗位适合度；
- 定制可信度；
- 命中的风险规则；
- 匹配优势；
- 能力缺口；
- 推荐项目；
- 使用默认或定制材料的原因；
- 引用证据。

### 8.9 简历生成

- 从已确认事实中选择和重排内容。
- 支持 PDF 和 DOCX 输出。
- 每条生成内容保存事实来源。
- 禁止新增无来源的技能、数字和经历。
- 用户可以预览、编辑并批准。
- 无法在 Boss 自动关联定制简历时，回退默认简历并提示原因。

### 8.10 问候语

- 高匹配岗位使用 JD 和真实项目事实生成个性化问候语。
- 一般、风险或失败岗位使用用户配置的默认问候语。
- 个性化问候语必须来自用户已确认的事实；任务启动后无需再次确认即可发送。
- 第一版不自动处理后续聊天。

### 8.11 默认简历图片发送

- 默认图片由简历库中的 PDF 首页生成，并由用户明确选为默认投递图片。
- 配置确认必须分别显示“默认简历图片：已配置/未配置”和“随投递发送：已开启/未开启”。
- 图片自动发送默认关闭；只有 `sendResumeImage=true` 且 `defaultResumeImageAvailable=true` 时执行。
- 项目 Chrome 扩展先在自身面板加载预览，确认后才向当前 BOSS 聊天注入文件；注入会触发平台立即发送。
- 面板可拖拽、可折叠；折叠后仍保留加载和发送操作，且 Skill 的稳定选择器不受布局状态影响。
- 插件不可用、目标会话不匹配或发送状态不明确时记录失败，禁止回退到任意本地文件或重复盲发。

### 8.12 执行预览与控制

- 支持按页面批量查看职位。
- 显示材料策略、分数、风险和生成状态。
- 启动前支持单个编辑、排除或切换材料。
- 用户启动任务后连续执行，不再逐项确认。
- 执行期间支持暂停、继续和停止。

### 8.13 投递记录与申请跟进

- 保存职位快照和投递时间。
- 保存使用的简历、问候语及其版本。
- 保存投递成功、失败、跳过和平台风控状态。
- 每次成功投递创建或关联一条求职申请，保留当时的匹配分数、材料版本和证据。
- 回复、面试邀请、面试轮次、Offer、拒绝、撤回和岗位失效以追加阶段事件记录，不覆盖历史事件。
- 职位快照列表的“跟进”操作必须打开弹窗，不在列表上方展开内嵌表单。
- 跟进弹窗展示当前申请阶段、投递材料摘要和阶段事件时间线，并允许追加事件时间、结果、轮次和备注。
- `has_communicated` 与 `has_interview` 只作为列表快速展示和旧数据兼容字段，由申请及阶段事件汇总生成，不作为正式统计事实源。

## 9. 隐私与安全

- 本地 API 默认只监听 `127.0.0.1`。
- 浏览器扩展与本地服务之间使用一次性配对令牌。
- GitHub Token 和模型 API Key 存入操作系统密钥链，不写入普通数据库或日志。
- 调用模型前展示并记录发送字段。
- 日志默认脱敏手机号、邮箱、Token 和 Cookie。
- 用户可以删除全部本地数据和向量索引。

## 10. 成功指标

第一阶段主要验证：

- JD 关键字段解析准确率；
- 风险条件误判率；
- 生成内容事实可追溯率，目标为 100%；
- 默认材料降级成功率；
- 用户启动并管理一批任务所需时间；
- 投递任务成功率及风控中止是否可靠。

不以“投递数量最大化”作为唯一指标。

## 11. MVP 范围

### 必须完成

- Skill、Kimi、项目图片扩展和本地服务的受控协作；
- 本地用户档案与一个或多个求职目标；
- 公开 GitHub 仓库导入；
- 项目标签和事实审核；
- PDF/DOCX/Markdown 简历导入；
- Boss JD 获取；
- 风险规则；
- 本地 RAG；
- 双分数匹配报告；
- 默认材料降级；
- 定制材料草稿；
- 批量执行预览、启动、暂停和停止；
- 问候语发送和投递记录。
- 默认简历图片的配置检测、预览、确认发送和失败守卫。
- 职位快照跟进弹窗、求职申请和阶段事件记录。

### 待验证

- Boss 是否支持按职位自动选择或发送不同的 PDF/DOCX 简历；
- 私有 GitHub 仓库的授权方式；
- 用户自带模型 API Key还是产品统一提供额度；
- 投递结果是否能够稳定获取已读、回复等状态。

## 12. 验收标准

MVP 验收需满足：

1. 用户可以完成首次配置并建立本地项目库。
2. 系统可以从 Boss 页面获得完整 JD 快照。
3. “985/211 优先”和“仅限 985/211”能够被区分并展示证据。
4. 命中风险条件的职位使用默认简历和默认问候语。
5. 高匹配职位能够从真实项目事实生成可追溯的简历草稿。
6. 任意 AI 调用失败时能够安全降级。
7. 未经用户主动启动任务不会执行投递；启动后无需逐项确认。
8. 账号出现平台限额或风控提示时立即停止后续投递。
9. 用户可以从职位快照打开跟进弹窗，查看时间线并记录回复、面试和最终结果；关闭弹窗不得修改数据，保存后列表摘要与时间线一致。
10. 图片发送只有在默认图片已配置且开关开启时执行；折叠或拖动面板不影响 Skill 调用，且不得因失败回退到其他文件。
