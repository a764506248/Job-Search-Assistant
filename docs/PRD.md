# Job Search Assistant 产品需求文档

## 1. 文档信息

- 产品名称：Job Search Assistant
- 当前版本：PRD v0.1
- 首发平台：Boss 直聘 Web
- 产品形态：浏览器扩展 + 本地知识库服务 + 用户自选云端大模型
- 目标用户：需要批量分析职位、定制求职材料并辅助投递的求职者

## 2. 产品目标

Job Search Assistant 帮助用户在处理大量职位时完成以下工作：

1. 获取并结构化解析职位 JD。
2. 识别学历偏好、工作方式、行业和其他用户自定义风险条件。
3. 从用户本地的项目库、经历库和简历库中检索与 JD 相关的真实材料。
4. 判断是否具备生成定制简历和个性化问候语的充分依据。
5. 资料不足、匹配度低或命中风险条件时，自动回退到默认简历和默认问候语。
6. 用户启动任务后，由扩展按既定策略自动执行 Boss 直聘沟通与问候语发送。
7. 保存投递材料版本和结果，为后续分析提供数据。

## 3. 非目标

第一版不包含：

- 自动编造项目、技能、学历、成果或量化指标。
- 没有用户主动启动任务的后台投递。
- 自动回复招聘者的后续聊天。
- Boss 直聘以外的招聘平台。
- 基于投递结果自动训练模型。
- 团队协作、企业招聘和 SaaS 管理后台。

## 4. 产品原则

### 4.1 真实性

生成的每条简历内容必须关联到经过用户确认的事实来源。没有来源的内容不得进入最终简历。

### 4.2 本地优先

项目、简历、个人资料、向量索引和投递记录默认保存在本机。云端模型只接收当前任务命中的必要片段。

### 4.3 可降级

任何 AI、RAG、模板渲染或文件生成环节失败时，不应中断整批任务，而应回退到默认简历和默认问候语。

### 4.4 用户控制

用户主动启动投递任务后，系统无需逐项或批量确认即可连续执行；用户可以随时暂停或停止任务。平台风控、账号限额、黑名单和重复职位会自动中止或跳过。

## 5. 核心概念

### 5.1 求职目标

由用户输入的职位方向，例如“AI 应用开发工程师”或“Java 后端工程师”。每个目标独立关联：

- 岗位关键词；
- 城市、薪资和行业偏好；
- 默认简历；
- 默认问候语；
- 风险规则；
- 匹配阈值；
- 简历模板。

### 5.2 风险条件

用户不希望在 JD 中看到、但默认不阻止投递的条件，例如：

- 985、211 或第一学历偏好；
- 外包、驻场；
- 单休、大小周；
- 特定行业或公司类型；
- 超出期望范围的经验要求。

命中风险条件时，职位使用默认简历和默认问候语。用户可将特定规则手动改成“禁止投递”。

### 5.3 岗位适合度

衡量用户与岗位要求的匹配程度，不代表材料生成质量。

### 5.4 定制可信度

衡量本地知识库中是否存在足够、真实且可引用的材料来生成定制简历。

只有岗位适合度和定制可信度均达到用户阈值时，系统才生成定制材料。

## 6. 用户流程

### 6.1 首次使用

1. 安装浏览器扩展和本地服务。
2. 创建本地用户档案。
3. 填写个人基本信息。
4. 创建一个或多个求职目标。
5. 上传历史简历并指定默认简历。
6. 设置默认问候语。
7. 连接 GitHub 并选择需要导入的项目。
8. 审核系统生成的项目资料和标签。
9. 配置云端模型 API。
10. 设置匹配阈值和风险规则。

### 6.2 项目入库

1. 用户提供 GitHub 仓库地址。
2. 本地服务读取仓库元数据和允许分析的文件。
3. 系统生成项目背景、职责、技术栈和候选标签。
4. 用户补充业务背景、个人职责和成果。
5. 用户确认事实及其可使用范围。
6. 本地服务生成结构化事实和向量索引。

### 6.3 职位分析与投递

1. 扩展从 Boss 页面获取职位列表和 JD。
2. 系统解析岗位要求并保留证据原文。
3. 执行风险规则和重复职位检查。
4. 本地 RAG 检索相关项目、经历和简历片段。
5. 云端模型生成匹配报告。
6. 根据双阈值选择定制材料或默认材料。
7. 系统展示批量执行预览，用户启动任务。
8. 扩展连续执行沟通和问候语发送，不再逐项确认。
9. 系统保存职位、判断、材料和投递结果。

## 7. 投递决策

| 状态 | 简历 | 问候语 | 默认动作 |
| --- | --- | --- | --- |
| 高匹配且资料充分 | 定制简历 | 个性化问候语 | 任务启动后自动投递 |
| 一般匹配 | 默认简历 | 默认问候语 | 任务启动后自动投递 |
| 命中风险条件 | 默认简历 | 默认问候语 | 任务启动后自动投递 |
| AI 或生成失败 | 默认简历 | 默认问候语 | 任务启动后自动投递 |
| 重复职位 | 无 | 无 | 默认阻止，可人工覆盖 |
| 公司黑名单 | 无 | 无 | 禁止投递 |
| 平台限额或风控 | 无 | 无 | 立即停止任务 |

默认建议阈值：

- 岗位适合度不低于 75；
- 定制可信度不低于 80。

具体阈值由用户按求职目标修改。

## 8. 功能需求

### 8.1 用户档案

- 维护基本信息、教育、工作经历、技能和联系方式。
- 字段可设置为：本地私密、允许发给模型、允许写入简历、允许写入问候语。
- 支持导入 PDF、DOCX 和 Markdown 简历。

### 8.2 求职目标

- 支持多个目标。
- 支持目标关键词、城市、薪资、行业和工作方式。
- 每个目标可设置默认材料、风险规则、阈值和模板。

### 8.3 GitHub 项目库

- 添加、更新、禁用和删除项目。
- 保存仓库地址、分支和同步版本。
- 自动提取技术栈和候选标签。
- 用户确认后才能将自动提取内容用于简历。
- 支持用户手工补充非代码事实。
- 私有仓库支持列为待确认项，第一阶段可先完成公开仓库。

### 8.4 标签体系

标签至少分为：

- 技术标签：Vue、Python、RAG、PostgreSQL 等；
- 业务标签：招聘、企业服务、电商、内容平台等；
- 能力标签：系统设计、性能优化、数据建模等；
- 角色标签：独立开发、负责人、协作者等；
- 结果标签：增长、降本、提效、稳定性等。

系统推荐标签，用户可以增加、删除、合并和确认。

### 8.5 JD 获取与解析

- 支持 Boss 职位列表和详情页。
- 保存原始 JD、来源 URL、采集时间和页面职位 ID。
- 提取职责、技能、经验、学历、学校偏好、薪资、地点和福利。
- 每个结构化判断必须保存对应的原文证据。
- 区分“硬性要求”“优先条件”“公司介绍”和“否定表达”。

### 8.6 规则引擎

- 支持关键词、数值、公司、行业和语义规则。
- 动作支持：提醒、降分、使用默认材料、禁止投递。
- 默认风险规则只将职位降级到默认材料。
- 规则结果必须展示命中证据。

### 8.7 RAG 检索

- 本地执行标签过滤、关键词检索、向量召回和重排。
- 只检索允许用于当前场景的事实。
- 返回来源 ID、相关性分数和原始证据。
- 不把整个知识库发送给云端模型。

### 8.8 匹配报告

报告至少包含：

- 岗位适合度；
- 定制可信度；
- 命中的风险规则；
- 匹配优势；
- 能力缺口；
- 推荐项目；
- 使用默认或定制材料的原因；
- 引用证据。

### 8.9 简历生成

- 从已确认事实中选择和重排内容。
- 支持 PDF 和 DOCX 输出。
- 每条生成内容保存事实来源。
- 禁止新增无来源的技能、数字和经历。
- 用户可以预览、编辑并批准。
- 无法在 Boss 自动关联定制简历时，回退默认简历并提示原因。

### 8.10 问候语

- 高匹配岗位使用 JD 和真实项目事实生成个性化问候语。
- 一般、风险或失败岗位使用用户配置的默认问候语。
- 个性化问候语必须来自用户已确认的事实；任务启动后无需再次确认即可发送。
- 第一版不自动处理后续聊天。

### 8.11 执行预览与控制

- 支持按页面批量查看职位。
- 显示材料策略、分数、风险和生成状态。
- 启动前支持单个编辑、排除或切换材料。
- 用户启动任务后连续执行，不再逐项确认。
- 执行期间支持暂停、继续和停止。

### 8.12 投递记录

- 保存职位快照和投递时间。
- 保存使用的简历、问候语及其版本。
- 保存投递成功、失败、跳过和平台风控状态。
- 后续版本可扩展已读、回复、面试、拒绝和 Offer 状态。

## 9. 隐私与安全

- 本地 API 默认只监听 `127.0.0.1`。
- 浏览器扩展与本地服务之间使用一次性配对令牌。
- GitHub Token 和模型 API Key 存入操作系统密钥链，不写入普通数据库或日志。
- 调用模型前展示并记录发送字段。
- 日志默认脱敏手机号、邮箱、Token 和 Cookie。
- 用户可以删除全部本地数据和向量索引。

## 10. 成功指标

第一阶段主要验证：

- JD 关键字段解析准确率；
- 风险条件误判率；
- 生成内容事实可追溯率，目标为 100%；
- 默认材料降级成功率；
- 用户启动并管理一批任务所需时间；
- 投递任务成功率及风控中止是否可靠。

不以“投递数量最大化”作为唯一指标。

## 11. MVP 范围

### 必须完成

- 浏览器扩展和本地服务配对；
- 本地用户档案与一个或多个求职目标；
- 公开 GitHub 仓库导入；
- 项目标签和事实审核；
- PDF/DOCX/Markdown 简历导入；
- Boss JD 获取；
- 风险规则；
- 本地 RAG；
- 双分数匹配报告；
- 默认材料降级；
- 定制材料草稿；
- 批量执行预览、启动、暂停和停止；
- 问候语发送和投递记录。

### 待验证

- Boss 是否支持按职位自动选择或发送不同的 PDF/DOCX 简历；
- 私有 GitHub 仓库的授权方式；
- 用户自带模型 API Key还是产品统一提供额度；
- 投递结果是否能够稳定获取已读、回复等状态。

## 12. 验收标准

MVP 验收需满足：

1. 用户可以完成首次配置并建立本地项目库。
2. 系统可以从 Boss 页面获得完整 JD 快照。
3. “985/211 优先”和“仅限 985/211”能够被区分并展示证据。
4. 命中风险条件的职位使用默认简历和默认问候语。
5. 高匹配职位能够从真实项目事实生成可追溯的简历草稿。
6. 任意 AI 调用失败时能够安全降级。
7. 未经用户主动启动任务不会执行投递；启动后无需逐项确认。
8. 账号出现平台限额或风控提示时立即停止后续投递。
